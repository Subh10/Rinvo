# Rinvo GitHub Action

The root `action.yml` exposes Rinvo as a composite GitHub Action. It calls a **running Rinvo API**; it does not install model weights or run speech inference inside the GitHub-hosted runner.

## Prerequisites

1. Deploy Rinvo somewhere reachable from the workflow runner.
2. Configure that deployment with a working TTS backend and authorized reference audio if required by the backend.
3. Verify `GET /health` and a real `POST /v1/audio/speech` request against the deployment before using the Action.
4. If the service is private, put it behind an authenticated HTTPS proxy and pass a short-lived token via a GitHub Actions secret. The Rinvo API itself does not implement authentication by default.

## Example workflow

```yaml
name: Generate voiceover

on:
  workflow_dispatch:

permissions:
  contents: read

jobs:
  speech:
    runs-on: ubuntu-latest
    steps:
      - name: Generate speech
        id: speech
        uses: Subh10/Rinvo@v0.1.0
        with:
          api_url: ${{ vars.RINVO_API_URL }}
          text: |
            Hello from Rinvo.
            This audio was generated by a workflow.
          output_path: artifacts/voiceover.wav
          # Optional; only if your reverse proxy requires a bearer token.
          bearer_token: ${{ secrets.RINVO_API_TOKEN }}

      - name: Upload generated WAV
        uses: actions/upload-artifact@v4
        with:
          name: rinvo-voiceover
          path: ${{ steps.speech.outputs.audio_path }}
```

Replace `v0.1.0` with a published immutable release tag once one exists. Do not commit API tokens or reference recordings. GitHub-hosted runners must be able to reach the API URL; localhost on the runner is not your own machine.

## Inputs and output

- `api_url` (required): base URL of the service; the Action appends `/v1/audio/speech`.
- `text` (required): text to synthesize.
- `output_path` (optional): destination path, default `rinvo-output.wav`.
- `bearer_token` (optional): sent as an Authorization header; only useful when your deployment's proxy validates it.
- `timeout_seconds` (optional): request timeout, default `180`.
- `audio_path` (output): path of the generated WAV file.

This Action is an API client. A successful Action run demonstrates that the configured remote service returned a WAV file; it does not itself prove that the remote backend generated natural speech. Validate the deployment with a real inference smoke test.
